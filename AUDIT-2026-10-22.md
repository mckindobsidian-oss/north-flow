# North project audit — 22 October 2026

Update, 23 October: desktop foreground sampling is now one second, exact
executable blocking replaces substring matching, and a native tray heartbeat
drives the authenticated sync bridge. The extension now displays today's
account-owned desktop activity. Pending native flush failures no longer trigger
a pull over unsent edits. Live signed-in product verification remains pending.

Scope: source inspection across React, extension, Tauri, Expo, shared rules,
schema/migrations, and current Git/build state. This is not a claim that every
platform was exercised live. Existing earlier checks are historical evidence;
only the targeted tracking checks were run for this audit.

## Implemented

- React: Focus/timer, tasks, task dates/calendar, themed Flow date ranges,
  hidden-site preferences, usage charts, readable surfaces, wallpapers, and
  four completion sounds. Shared Flow creation covers websites and applications.
- Extension: website blocking via DNR, scheduled/daily/session rules, themed
  block page, one-minute allowance, local usage history, account handoff and
  REST synchronization. Rules are cached locally for offline enforcement.
- Desktop: locally bundled React frontend plus Rust foreground-process usage,
  process-rule enforcement, tray and persisted native state. It does not need
  a hosted website to render. A Windows debug executable exists.
- Account: Supabase identity, profile/task/focus synchronization and local
  write queue. React supports owner-filtered Realtime invalidation for profile
  and usage records; extension uses alarms/REST. Schema declares owner RLS and
  unique normalized usernames. Earlier live RLS checks are in PROGRESS.md.
- Usage: collector IDs avoid different devices overwriting the same daily row.
  Reporting sums device rows and reconciles legacy aggregates heuristically.

## Changed in this audit

- Only the selected HTTP(S) tab in the focused browser window is tracked.
  Background-audio preferences no longer add background tabs.
- Idle or locked state pauses tracking, with a 60-second idle threshold.
- Added Chrome idle permission and an idle-state listener. Reload the extension
  and accept the permission if requested. Existing historical totals remain.
- Verified three focused checks: foreground selection, internal-page exclusion
  and fractional samples, and manifest validity. Worker syntax check passed.
  Live focus/idle behavior in the installed extension remains to be checked.

## Remaining, in priority order

1. **Live authentication and enforcement verification.** User reports saving
   the Supabase loopback redirect. Retry desktop Google sign-in with the rebuilt
   executable. Then verify a website-created limit appears in the installed
   extension, blocks at its threshold, and survives account switch/offline use.
   Verify desktop enforcement with a disposable application. Source tests and
   a successful app launch do not prove these complete workflows.
2. **Account-wide allowance accounting.** Rule definitions synchronize, but
   `background.js:currentUsageSeconds` reads browser-local usage and Rust daily
   app enforcement reads native-local usage. A shared 30-minute budget is not
   currently one atomic remaining allowance across devices. Device totals also
   cannot distinguish overlapping concurrent activity from sequential use;
   timestamped intervals/server reconciliation are needed for that guarantee.
3. **Conflict-safe synchronization.** `sync.js` replaces whole cached profiles
   on pull and prunes task/board lists on push. Concurrent edits can overwrite
   or delete another device's changes. Reconnect safeguards improve retries but
   do not implement revision checks or per-record conflict resolution.
4. **Mobile readiness.** `apps/mobile/lib/auth.js` imports the sync engine using
   `../../react-app/...`, which resolves under `apps/` rather than the repository
   root; it needs `../../../react-app/...`. AsyncStorage is declared and Google
   PKCE code exists, contrary to older README claims. Device builds, OAuth
   callbacks, persistence and sync still require verification. Android native
   usage/blocking and iOS Screen Time entitlements/enforcement remain unfinished.
5. **Release packaging and deployment.** Desktop output is a debug executable,
   not a signed release installer or auto-updater. No verified production North
   origin is configured; the unrelated north.vercel.app example was removed from
   extension trust. Add the actual owned domain to both manifest/runtime origin
   checks and Supabase once deployed. Current edits are uncommitted/unpushed;
   the existing GitHub snapshot does not contain them automatically.
6. **Final UX/accessibility/performance pass.** The themed UI and responsive
   work are implemented; a fresh installed-browser/native/mobile visual pass
   remains. Current production JS is about 625 kB minified (178 kB gzip), with a
   build-size warning. Some older READMEs/roadmap entries contradict newer code.
   Legacy Board/schema compatibility remains intentionally retained, not a new
   product feature. Spotify embed exists; it is not proof of account playback
   integration. Google Calendar integration is outside the requested active UI.

## Access

- Website: http://127.0.0.1:5174/ while the local development server runs.
- Desktop: apps/desktop/src-tauri/target/debug/north-desktop.exe.
  Double-click in File Explorer. Closing hides the app to the tray; Quit exits.
- Extension: reload the unpacked apps/extension directory from the browser's
  Extensions page, then use Connect to North with the local website signed in.

Release conclusion: ready for local testing, not yet proven ready to publish.
